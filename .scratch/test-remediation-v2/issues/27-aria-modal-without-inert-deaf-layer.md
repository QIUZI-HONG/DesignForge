# 27: fix · `aria-modal` 声称模态，背景却没被 inert：焦点合法离层后这一层听不见按键

**What to build:** 浮层的**模态声明**与**实际行为**必须一致。现状：`Modal.tsx:89` / `Drawer.tsx:118` / `Overlay.tsx:76` 都带
`aria-modal="true"`，那是在告诉辅助技术「层外的内容不可交互」；但实现里**没有任何一处**把背景置为
`inert` 或 `aria-hidden`——背景照常可点、可 Tab、可编程聚焦。后果不是「不合规」这么轻：
Esc 与 `trapTabKey` 都挂在层自身元素的 `onKeyDown` 上（`Drawer.tsx:113`、`Modal.tsx:84`、`Overlay.tsx:81`），
只收得到**从层内冒泡上来的**按键，
所以焦点一旦被合法交给层外的元素（吐司、下拉、第三方 portal 面板、`page.focus()` 类调用），
这一层立刻**又聋又仍宣称模态**：关不掉、Tab 直接跑到画布背后，而读屏器听到的还是「在对话框里」。
这条已被测试钉成事实（`packages/ui/src/components/overlay.test.tsx` 的
「焦点在层外时这层是聋的：同一次 Esc 到不了层」——那条**故意**断言抽屉关不掉）。

**与票 25 的分工**：票 25 收口的是「**本层**的控件因 `disabled`/摘除而不能再持焦 → 焦点无处可去 → 接回」。
它的判据 ① 明确只认本层的事件，判据 ③ 明确**不**把合法交给层外的焦点抢回来（那会把浮层变成抢焦点的牢笼，
实测还会打断既有「Tab 回环」用例）。所以「焦点在层外」这一整类**是票 25 有意不收的**，不是漏的——本票收它。

  ① **背景置 `inert`**（对齐 `aria-modal` 的语义，Tab 与点击在浏览器层面就到不了背景，`trapTabKey` 可退役或降级为兜底）——
  要处理嵌套层栈（栈顶开时只对「非本层祖先链」的子树加 inert，关掉时逐层归还，别把上一层也锁死）、

  ② **按键上收到 document 捕获层**（Esc/Tab 不依赖焦点在层内）——改动小，但 `aria-modal` 的声明与实际仍然不符，
  读屏器与指针用户照样能进背景。按「声明与行为一致」这条，①是正解，②只是止血；选②必须写明它不解决声明问题。
