# 03: 本地建议生成器与接线（断点二·下）

**What to build:** 未配置 key 的用户在 AI 抽屉提交后，得到**真实可读**的本地建议而不是空结果：daemon 侧新增确定性纯函数生成器，输入提示词、输出结构化中文建议（识别按钮/颜色/圆角/布局/文本等关键词族，给出分步操作建议）。约束（来自 spec，均为既有纪律的延伸）：输出走既有 AI 契约（content + suggestions）；**不产出 Design IR、不触碰命令栈**（P5 边界）；同输入同输出（表驱动测试可断言）；结果在 UI 上以独立角标明确标注「本地建议 · 非 AI 生成」，与在线结果视觉同构但来源可辨。P5 落地时生成器降级为「上游不可用兜底」，接口不变（该重叠风险已被用户接受）。

**Blocked by:** 01 (SSE CORS——浏览器端到端可见的前提), 02 (诚实化——角标与文案口径先定，生成器结果直接套用)

**Status:** ready-for-agent

- [ ] 生成器纯测：表驱动断言关键词族 → 建议结构；同输入同输出；空/无关键词输入有合理兜底
- [ ] daemon 路由信封断言：未配置 key 的响应 content 为真实建议文本（非空串），suggestions 结构合法
- [ ] 组件测试：降级完成态渲染建议正文与「本地建议 · 非 AI 生成」角标
- [ ] 浏览器实测（未配置 key）：提交「给首屏加一个主按钮，并把圆角统一为 8」类提示词，得到可读建议
- [ ] 「与真响应同构、UI 不为降级写分支」的既有架构纪律未被破坏
