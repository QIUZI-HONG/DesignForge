# Spec：测试执行阶段 1——三断点修复 + 守护用例落地 + 两态门禁接 CI（v1）

> 状态：待发布 GitHub Issues（label `ready-for-agent`）。
> 规范源引用（不复制内容）：`docs/quality/fullstack-test-design-2026-11-03.md`（下称《测试设计》，99 条用例的唯一真源）·
> `docs/quality/ux-audit-2026-10-30.md`（三断点 3.1/3.2/3.3）· `docs/agents/implementation-workflow.md`（三态门禁/工作树/CI 差异纪律）。

## Problem Statement

测试设计已交付，但测试执行未发生。作为维护者，我看到三个缺口同时存在：UX 审计的三个 P0 缺陷（AI 抽屉在浏览器端必然 Failed to fetch、AI 结果区呈现从未发生的「校验/编译」假步骤、命令面板样式未挂载+键位不一致）没有修复、也没有回归拦截；约 30 条 P0/P1 缺口用例（崩溃注入、跨进程冲突、路径穿越、SSE 分档、本地态边界）尚未写成代码；AI/出图/MCP 三个两态取证门禁未接入 CI。当前 CI 的实际拦截面止步于 lint/typecheck/单测/4 守卫——数据丢失与本地特权面这些 P0 风险在自动化上是裸奔的。按本仓三态门禁纪律，未实现当绿即假绿：测试结果与产品宣称能力之间存在诚实性缺口。

## Solution

按《测试设计》§8.2 阶段 1 执行（零新基建，一个迭代内可完成）：

1. 修复三断点，且每个修复各转一条红→绿回归（P0 缺陷→门禁转化律）；
2. 补齐 daemon 集成层 P0 缺口用例与 SSE 通道两档缺口；
3. `verify-ai-two-state` / `verify-image-two-state` / `verify-mcp-stub` 以非浏览器口径接 CI；
4. 全程遵循既有纪律：临时数据根+独立端口、证据落仓外、门禁实况两处同源。

## User Stories

1. 作为设计者（维护者），我要 AI 抽屉在浏览器端真正收到 SSE 流式响应，所以「受控 AI」支柱对真实用户成立，而非只在命令行 curl 下成立。
2. 作为维护者，我要流式 SSE 通道的 CORS 回归用例常驻测试树，所以未来任何改动都不会再让流式响应绕过 CORS 策略而不被发现。
3. 作为维护者，我要 validate/compile 假步骤被移除或接上真实出口，所以界面不会向用户展示根本没有发生的「校验/编译」阶段。
4. 作为维护者，我要命令面板样式被构建产物真正加载、键位与速查卡口径一致，所以审计 3.3 的三个断点不再复现。
5. 作为实现子代理，我要 daemon 崩溃注入用例（写入中途 SIGKILL、多轮幂等）常驻测试树，所以任何破坏「原子写+提交点」语义的改动立刻红。
6. 作为维护者，我要跨进程并发写用例钉死「要么成功要么 409 conflict」契约，所以两个 daemon 实例同时写同一文档的行为有机器可判的边界。
7. 作为安全敏感的桌面用户，我要路径穿越语料（相对逃逸/NUL/非 NFC/软链）在文档与导出链路都有对抗用例，所以恶意文档名写不出数据根之外。
8. 作为维护者，我要 SSE mock 分档用例（半行拆帧/中途断流/非事件流/零 data），所以上游网络异常时的降级行为有确定性预期。
9. 作为维护者，我要三个两态门禁进 CI，所以「无上游降级态」与「mock 上游真态」每次提交都被复核，防止桩转真时静默退化。
10. 作为测试执行代理，我要每条用例能从《测试设计》的用例 ID 直接定位步骤/预期/自动化层级，所以开工不需要重新考古。
11. 作为维护者，我要本地态配额满/隐私模式降级有显式用例，所以「本地保存失败」路径既不白屏也不无提示丢数据。
12. 作为维护者，我要版本快照回滚链路（含回滚前自动快照）进入回归集，所以回滚能力永不退化。
13. 作为毕业设计评审人，我要每个 P0 缺陷的关闭都附带一条红转绿门禁，所以质量声明有完整证据链（缺陷→修复→回归→CI）。
14. 作为实现子代理，我要门禁实况两处同源的维护要求写进票面，所以接 CI 的票不会让实况表停留在旧口径。
15. 作为桌面用户，我要 3.1 的修复不扩大鉴权范围（Origin:null 放行等已登记取舍维持现状），所以本票行为变化最小、可独立回滚。
16. 作为维护者，我要导出链路失败码分派（timeout/daemon_offline/daemon_invalid_response/export_render_failed）有常量级断言，所以面板文案与失败码永不漂移。

## Implementation Decisions

- **三断点修复取向**（具体方案由实现票按架构文档裁定）：
  - 3.1：流式通道补齐 CORS 头。保持流式直写语义不变；头部取值必须与既有 CORS 策略同一真源（白名单回显 Origin、vary、Origin:null 恒放行口径均不变），禁止复制一份白名单逻辑形成双真源。本票只修「流式通道无放行头」这一个缺陷，不扩大鉴权面（本地 pairing token 属残余风险另票）。
  - 3.2：最小收口=移除假步骤并使时序真实化，UI 文案同步修正；「AI 文本→Design IR 编译出口」是独立后续票，不塞进本 spec。
  - 3.3：样式表真正进入构建产物 import 链；实现键位与审计清单对齐（两键位可开或清单改口径，二选一并同步速查卡）；速查卡完整入视口。
- **用例落位**：daemon 集成用例进 daemon 测试树（自起临时实例+临时数据根，禁连真实实例）；SSE mock 分档用例进 daemon；web 缺口用例进对应 feature 测试树。步骤与预期以《测试设计》用例 ID 为唯一真源，本 spec 不重复。
- **CI 接入口径**：三个两态门禁以「非浏览器 + mock 上游」并入现有 verify 链；runner 慢 3–4× 的教训=只放宽超时上限、不放宽断言；CI 无 gh 凭据按占位凭据+fetch 桩口径（ingest 冻结样本先例）。
- **门禁实况 DoD**：任何门禁的实现/接 CI/退役，必须同一票内同步两处实况行（实现工作流文档与根 AGENTS），否则按旧口径开工的下一个会话会踩空。
- **提交纪律**：一票一工作树、每模块即提交、中文 Conventional Commits、对照证据一律落仓库外证据目录。
- **范围纪律**：不引入新测试框架、不新增接缝；不动性能/视觉基线（属阶段 2/3）；不碰鉴权（R-1 另票）。

## Testing Decisions

- **好测试只测外部行为**：HTTP 契约（状态码+稳定错误码）、文件系统终态（权限位、JSON 可解析、无临时残留）、计算样式与渲染出的 UI 状态——不测内部调用图与实现细节。
- **接缝四层（全部既有接缝，零新增）**：引擎纯函数单测 → daemon 集成（临时实例 + inject/spawn）→ 组件测试（jsdom）→ 脚本门禁（node 自带 test runner）。浏览器层门禁维持既有挂点，本阶段不接。
- **先例**：引擎固定种子模糊测试、daemon 对抗性安全测试、mock 上游两态取证、临时实例 harness——新用例与这些同构，优先复用其工具函数。
- **执行序**：P0 缺口用例 → 两态门禁接 CI → P1 缺口；P2 不在本阶段。

## Out of Scope

- 阶段 2/3/4：视觉参照集冻结与像素对照门禁接 CI、性能基线校准转正与动效断言实现、契约守卫实现、属性测试选型、夜跑故障注入。
- 残余风险产品决策项（R-1~R-11）：本地鉴权/pairing token、版本快照 daemon 持久化、自动保存、双窗口同步承诺、导出真光栅化、格式迁移器、20k 档性能阈值等。
- 真实上游（DeepSeek/ComfyUI）联调验收——一律 mock。
- a11y 系统性测试、浏览器兼容矩阵、Vercel 线上一致性验证。
