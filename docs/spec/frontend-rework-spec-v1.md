## Problem Statement

设计师使用设界时感受到的是「功能正确但体验像演示件」：动效从未生效（时长令牌单位缺陷导致全部 transition/animation 被浏览器静默丢弃）、视觉精致度与 Figma 本体有观感差距、页面之间的导航/加载/空态/错误反馈不成体系、前端实现存在样式双轨与注册间接层等结构债。同时，P0 时期的像素门禁只锁「静态外观与参照截图一致」，手感/流程/反馈/性能这些体验维度没有任何验收抓手——改得好坏全凭感觉，改坏了也不报警。

## Solution

按 ADR-0005 对前端做**整体改版、保架构重实现**：保留 feature 域/插槽注册/会话-引擎分离的总体架构，域内重写实现并收纳过度间接层，engine/contracts 不动。建立**双层验收**：A 层把对标页的像素断言降级为结构布局断言（DOM 几何快照），B 层新增体验验收（动效生效/流畅度/动线步数/四态覆盖/可达性五门禁）；视觉允许**设计超越**（登记在册的有意差异），参照集版本化重冻结。按阶段 0-4 交付，每阶段有独立验收。

## User Stories

动效与手感：

1. 作为设计师，我希望面板、浮层、抽屉有真实的出入场动效，所以界面有「活着」的手感而不是元素瞬移的演示件。
2. 作为设计师，我希望悬停与按下有过渡反馈，所以能确认哪些控件可交互。
3. 作为设计师，我希望全局动效遵循统一时长与缓动档，所以整套界面节奏一致不突兀。

画布手感：

4. 作为设计师，我希望拖拽与框选在大文档下依然跟手流畅，所以编辑大设计稿不被卡顿打断心流。
5. 作为设计师，我希望缩放画布以光标为锚点，所以放大查看细节时目标不会飘走。
6. 作为设计师，我希望吸附参考线在对齐瞬间出现，所以精确布局不需要反复核对坐标。
7. 作为设计师，我希望双击文本即可进入编辑且光标落点正确，所以改文案不必绕路。
8. 作为设计师，我希望撤销重做即时可见，所以大胆尝试而不怕不可回退。

面板与编辑器：

9. 作为设计师，我希望图层面板提供树形展开、重命名与拖拽排序，所以能管理复杂图层结构。
10. 作为设计师，我希望切换选中时 Inspector 即时刷新且键盘焦点落位合理，所以连续微调不打断节奏。
11. 作为设计师，我希望 Inspector 数值支持拖拽 scrubbing，所以微调尺寸/间距不用打字。
12. 作为设计师，我希望投影、内阴影、层模糊可见可调，所以设计稿有层次感。
13. 作为设计师，我希望自动布局支持主轴 fill 伸缩，所以还原真实响应式界面。

导航与流程：

14. 作为键盘优先的设计师，我希望 `Cmd+/` 呼出命令面板并支持中文模糊搜索直达全部命令，所以任何功能两秒可达。
15. 作为设计师，我希望长按修饰键显示快捷键速查浮层，所以不用背键位也能逐步学会快捷操作。
16. 作为设计师，我希望「首页 → 新建/打开 → 编辑 → 保存 → 返回」是固定且可预期的动线，所以不必重新学习产品。
17. 作为设计师，我希望「市场 → 装载资产 → 回编辑器」动线连贯，所以技能市场的资产真正进入我的设计流程。

反馈体系：

18. 作为设计师，我希望每个页面的空/载/错/成功四态齐备且风格统一，所以任何等待与失败都被明确告知。
19. 作为设计师，我希望列表类页面加载时看到骨架屏而不是空白，所以知道系统在工作。
20. 作为设计师，我希望 AI 生成与本地出图这类长任务有清晰的阶段反馈和失败语义，所以不会把降级当成功、把失联当排队。
21. 作为设计师，我希望超大导出在发起前被预检拦截并给出人话提示，所以不会点导出后收到一个莫名的 500。

可达性：

22.作为键盘与读屏用户，我希望全组件有可见焦点环，所以不用鼠标也能确认当前位置。
23. 作为读屏用户，我希望画布内容有可访问的替代表述（配合图层面板），所以不依赖视力也能了解画布结构。

结构与可维护性：

24. 作为维护者，我希望客户端引导只有一个入口和声明式注册表，所以插槽注册时序不再脆弱、新增插槽不再需要散点挂载。
25. 作为维护者，我希望应用层样式与组件样式单轨化（内联仅留几何算式场景），所以改样式只看一处、主题切换只有一条路径。
26. 作为维护者，我希望令牌单位有机器守卫（时长必须是 ms），所以「两边一致地错」的静默缺陷永不复发。

验收与门禁：

27. 作为维护者，我希望对标页有结构布局断言（几何锚点而非像素差异率），所以设计超越不会被误判为回归、布局漂移也逃不掉。
28. 作为维护者，我希望「动效实际生效」有门禁断言，所以动效从修复日起受保护。
29. 作为维护者，我希望渲染计数与帧时长经统一观测通道可被门禁读取，所以性能与剔除率有客观依据而非体感。
30. 作为答辩评审，我希望设计超越有登记簿，所以「有意的超越」与「无意漂移」可以区分并分别评价。

参照集：

31. 作为维护者，我希望参照集版本化重冻结且用途明确（B 级人工验收对照物 + 像素诊断基线），所以验收口径切换有干净的锚点。

## Implementation Decisions

**总体口径（ADR-0005）**

- 保架构重实现：feature 域划分、插槽注册机制、会话-引擎分离保留；域内重写实现；engine 与 contracts 的对外行为不动（contracts 仅允许为观测通道做**只读扩展**，见下）。
- 双层验收：A 层 = 对标页结构布局断言（DOM 几何快照，阈值 ±2px）；B 层 = 体验五门禁（动效生效/性能/动线/四态/可达性）；视觉差异走 B 级「视觉等价」人工验收。
- 设计超越登记制：九项 v0 范围（动效语言、海拔应用、焦点环、骨架屏、命令面板、数值 scrubbing、快捷键速查卡、空态引导、可达性）逐项登记生效；未登记差异视为漂移，由 A 层断言拦截。
- 参照集版本化重冻结（版本递增），用途 = B 级人工验收对照物 + 像素诊断基线；像素差异率不再作为通过线。

**渲染观测 seam（会话裁决新增，唯一新低层 seam）**

- 把渲染循环已有的绘制计数（节点数/剔除数/文本 run 数）与帧时长，经**既有诊断/遥测面**暴露为可编程读取的观测通道：HUD 已有展示通道，扩展为门禁可查询（同源只读读取），不新造协议、不加独立上报链路。
- 该通道是 verify:perf（M2/M7）与 verify:motion 的数据源；daemon 侧遥测仅接收汇总（沿用 JSONL），不逐帧上行。

**阶段 0（缺陷修复 + 引导收口）**

- 时长令牌单位缺陷修复：序列化器为时长档增加 ms 后缀分支（数字默认补 px 的规则仅作用于长度类）；tokens 一致性测试同步修正预期值。
- guard:tokens 增加单位合法性断言：时长必须 ms、长度必须 px、字重/行高/层级必须无单位。
- 统一客户端引导：一个 bootstrap + 声明式注册表，替代散点 `return null` 引导件；编辑器页只挂壳与引导。

**阶段 1（设计系统底座）**

- 样式单轨化：应用层内联样式对象收敛为组件类/CSS，内联仅保留几何算式场景；两轨都受 guard:tokens 约束。
- 设计系统组件补齐：树控件（图层）、数值步进 + scrubbing、色板/字号选择、Tab/折叠面板、图标补全；新组件状态族登记。
- 令牌 v2：在既有阴影/缓动/时长词汇上增加海拔语义档（页面/浮层/弹层）、焦点环令牌、动效语义档（进入/退出/强调）。
- 命令面板：全命令可达 + 中文模糊搜索，复用编辑器命令注册表为唯一命令源。

**阶段 2（编辑器域重做）**

- 画布手感项：拖拽/框选/缩放锚定/吸附时机/文本编辑进入；效果渲染接入绘制管线（投影/内阴影/层模糊——数据模型已备）；自动布局主轴 fill；Inspector 重写（含 scrubbing）；图层面板树控件。
- 渲染观测通道在本阶段接入（阶段 0 只留挂点）。

**阶段 3（全局流程反馈）**

- 动线固化为可断言清单（首页→编辑→保存→返回；市场→装载→回编辑；设置→凭据→AI 状态）。
- 四态覆盖矩阵补齐；AI/出图长任务等待反馈。
- 已知缺陷的**前端可见体验面**修复（导出超限预检提示、AI 401 语义文案、出图重启/取消的状态呈现、daemon 500 的分因文案）——缺陷主体修复仍归各自 Issues（#83/#90/#93/#98/#104），本 spec 只收前端呈现层。

**阶段 4（参照集重冻结 + 门禁切换）**

- 新参照集冻结（版本 + 日期 + 哈希）；verify:figma-* 系列改造成 verify:layout-*（几何快照比对）；像素对照降级为诊断工具（不拦合并，产出差异热图供 B 级人工验收）。
- acceptance-standard 升 v2（结构断言 + 体验层口径）。

**性能指标**：沿用《对标与优化报告 v1.1》§4（M1-M7、确定性文档生成器、初始目标值待基线校准——先测后优化，Worker 化/空间索引不在本 spec 内）。

## Testing Decisions

- **好测试只测外部行为**：门禁走真实链路（真 daemon 子进程 + Next 生产构建 + 真 Chromium），断言用户可见结果——几何快照、计算后的动效值、任务步数、四态覆盖、可达性属性、帧统计；不测组件内部实现。
- **seam 布局（会话裁决）**：门禁层单 seam 家族（既有 verify-* 惯例）承载全部新门禁：`verify:layout-*` / `verify:motion` / `verify:perf` / `verify:flows` / `verify:states` / `verify:a11y`；外加 `guard:tokens` 单位断言与引擎侧 vitest 微基准。唯一新低层 seam 是渲染观测通道（挂既有诊断/遥测面）。
- **先挂点后转正**：新门禁一律三态退出码纪律接入（无实现时 `exit 2` 显式阻塞，禁假绿），证据落盘沿用 `df.*.evidence/v1` 模式。
- **Prior art**：verify-daemon（每路由「一成功一失败」契约冒烟）、verify-ai-two-state / verify-image-two-state（真态/降级态同构两态验证）、e2e-smoke（真 daemon + 生产构建 + 真 Chromium，steps=0 即 fail）、guard:tokens（令牌机器守卫）、渲染计数器（绘制统计已有）。**教训引用**：tokens 一致性测试「两边一致地错」——一致性断言之外必须叠加单位合法性独立断言。
- 动效断言取计算样式（animation/transition 时长 ≠ 0 且单位为 ms），防同类静默失效回归。

## Out of Scope

- 矢量路径、布尔运算、原型交互、导入器（《对标与优化报告 v1.1》P-6/P-7/P-8/P-9，维持原段位）
- 受控 AI 提案/写入管线（A0）及 AI 特性（A1-A8）——对应 Issues #91，独立 triage/spec
- 序列化版本迁移策略与非法 `$version` 拒绝（Issues #87 修复主体）——属 engine 边界，独立工程票；本 spec 仅依赖其结论
- 市场数据质量收口（P-10）、guard:deps 实现、research 分支合并、comfy 收敛（E-1/E-2/E-3 独立小票）
- 已知缺陷的**非前端主体修复**（#83/#90/#93/#98/#104 归各自票）
- 多人协同（主动取舍不变）、AI 供应商边界任何变更（严格 DeepSeek + ComfyUI 边界内）
- Worker 化与空间索引（待 verify:perf 基线数据后再立项）
