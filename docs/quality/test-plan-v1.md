## 2. 测试策略

### 2.1 分层策略（真链路优先，能高不低）

| 层 | 内容 | 接缝 | 判定 |
|---|---|---|---|
| L1 单元/组件 | 引擎、UI、web 组件、daemon 服务、ingest、cli 的纯逻辑 | vitest（jsdom / 纯 Node） | 全绿 |
| L2 契约与门禁 | 三态退出码、证据 JSON、哈希复算、对抗夹具 | `scripts/verify-*.mjs`、`guard-*.mjs` | 0=通过；1=真违规；2=阻塞（非通过） |
| L3 浏览器门禁 | 真实页面：画布挂载/交互、市场、自设计页、评审交互、两态面板 | playwright-core（chromium-1243，headless + **生产构建**） | 同上三态 |
| L4 e2e 用户路径 | 真 daemon + 生产站 + 真 Chromium：首页/编辑器/导航/画布 | `scripts/e2e-smoke.mjs`（场景自动发现） | 全步骤 pass |
| L5 桌面壳 | 冒烟（装载+安全基线）、交互存活、壳内对照 | `verify-shell-parity.mjs` 三段 | 0/1/2 三态 |

### 2.2 设计原则

1. **禁止假绿**：一切「未实现/前置不成立」必须 `exit 2` 并点名原因；断言必须可复核（证据 JSON + 截图/日志哈希）。
2. **真链路优先**：能用浏览器/真 daemon 断言的，不用桩替代；桩必须显式标注（MCP / 市场装载写入）。
3. **异常与边界是重点**：空态/错误态/禁用态/边界输入（超长/非法字符/重名/负值/极端数值/特殊字符）逐项覆盖。
4. **测试不得假设开发机特产**（gh 凭据/Electron 二进制/显示器/仓外证据）——CI 差异清单为准。
5. **门禁不得被调弱**：注入面（假二进制/窗口参数）必须带下限校验与证据标记。

### 2.3 用例设计方法与覆盖

- 等价类 + 边界值 + 状态迁移（文档：新建/保存/重开；评论：草稿/发布/解决/重开；版本：保存/对比/恢复/删除）。
- 交互白名单 13 类（选择/移动/缩放/旋转/画布缩放/平移/复制粘贴/层级/编组/撤销/对齐/吸附/文本编辑）逐类有用例。
- 安全：路径穿越 5 种编码变体、文档名注入、CORS 白名单正反、凭据 0600、依赖漏洞审计。
- 数据面：六环判据链（请求纪律/认定/评分/index/检索/证据复跑）+ 与 CLI 的检索互证（「幻灯片」78=78）。
- 用例规模基线（实测）：全仓单测 **2756 例**；e2e **63 步**；浏览器门禁 ≥ 40 项交互/挂载断言；市场门禁 6 态挂点。

### 2.4 环境与数据

- 合并后 `main`（`2eaf9af` 并入后），node 24 / pnpm 10.33.2 / biome 2.5.15 / vitest 5。
- Chromium：`~/.cache/ms-playwright`（playwright-core 1.63 锁 chromium-1243）；WSLg（DISPLAY=:0）用于壳门禁。

- 证据：本计划全部证据落 `~/df-evidence/quality-2026-10-17/`（日志 + 摘要），仓库只存本文件与报告。

### 2.5 准入 / 准出准则

**准入**：代码已合并（#40/#42）、CI 绿、依赖安装就绪、测试实例可起。
**准出**：

## 4. 缺陷管理

- **分级**：A=阻断（主路径不可用/安全受损）；B=严重（功能不可达/规格未达）；C=一般/观察。
- **流程**：发现 → 复现步骤与证据 → 登记（GitHub issue 或报告附录）→ 修复 → 同接缝复跑 → 关闭。
- **登记口径**：阻塞（exit 2）不等于缺陷，但**必须**在报告点名原因；已知 flake 单列并标注复现条件与观测轮次。
- **回归资产**：所有修复固化为 e2e/门禁断言（批次 4 的 editor/nav 场景即此类）。
