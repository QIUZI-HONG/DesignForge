### 1.4 缺陷 DEF-R1（产品级，已修复）

**现象**：市场列表固定 `limit=60` 且无分页——索引 344 个资源中约 284 个在 UI 上不可达；中文检索「幻灯片」服务端 78 命中，界面只显示 60 张，且无任何「还有更多」的提示。

**证据**：daemon `GET /market/query?limit=60&offset=60` 返回不同批（证明分页契约完备）；`filters.ts` 默认 `limit=60`；页面无 offset 累加；机器人 v3 优化后实测 **60→120 张，进度「已加载 120 / 344」**。

### 1.5 验证方式（阶段 1）

- 机器人 v3：`node robot-full-v3.mjs` → 68/68 通过（结果 JSON + 16 截图）；空库态在干净数据根上验证。
- 既有回归资产：`pnpm e2e:smoke` 63/63 步（home 8 / editor 17 / nav 21 / canvas 10 / 编辑器门禁 7）。

## 阶段 2 · 企业架构师：缺陷分析与改进方案

### 2.1 目标

对阶段 1 的真实缺陷做架构级归因（边界、契约、单点、数据流），给出可落地的改进方案与取舍理由。

### 2.2 架构分析（DEF-R1）

- **契约层（无缺陷）**：`@dforge/contracts` 的查询参数含 `limit/offset`；daemon `routes/market.ts` 解析二者，`service.ts` 以 `matched.slice(offset, offset+limit)` 分页；`api.buildMarketQueryUrl` 支持 offset。**分页能力早已存在，缺的是消费侧。**
- **页面层（缺陷所在）**：`app/market/page.tsx` 用 `useMarketQuery(params)` 一次性取数；`toQueryParams(filters)` 固定 `limit=60`；无 offset 状态、无累加、无「还有更多」的可见性提示。检索路径同样被截断（78→60）。
- **根因归类**：**读模型缺少「分页视图态」这一层**——不是后端能力缺失，也不是组件缺陷，而是「查询 → 渲染」之间少了一个可累积、可重置、可判终点的状态机。
- **方案对比**：
  | 方案 | 取舍 |
  |---|---|
  | 页码分页（1/2/3…） | 需要导航/路由或页码态，与「本地优先、单页浏览」的轻量心智不符；市场卡片流更适合增量 |
  | 一次取全量（limit=344） | 违背后端 200 上限与长列表渲染成本；搜索/筛选每次全量 |
  | **增量「加载更多」+ 进度/终点**（选用） | 与 Figma 资产面板/市场流的浏览心智一致；复用既有 `limit/offset` 契约；失败可重试、已载内容不丢 |
- **落地结构（单点原则）**：新增 `useMarketPagination`（features/market 内唯一取数缝的扩展）——首屏复用 `useMarketQuery`，增量按 `offset=已载数` 请求；累积以**参数序列化键**隔离（过滤/检索/排序变化自动失效，旧响应按 key 丢弃）；追加按 id 去重（防 offset 漂移重复卡）；终点以服务端 `total` 或空页判定。纯函数 `appendMarketPage/hasMorePages` 可单测。
- **为什么不是在组件里拼**：组件保持纯 props（既有纪律）；分页状态机与取数同缝，避免「卡片/列表/页脚」各自持有 offset 的散装实现（Shotgun Surgery 的反面）。
- **不变量**：无参/无服务端 total 时退化为「一页到底」；客户端过滤（许可/来源/已装载/精选）语义不变（仍在当前已载结果集上做并如实声明）。

### 2.3 输出与验证

- 输出：本分析 + 代码改动（阶段 3）+ 单元/页面/hook 三层测试。
- 架构验收：`pnpm verify` exit 0（新增 3 个测试文件、8 条用例）；daemon 契约未改动（无 API 破坏）。

## 阶段 3 · 用户体验设计师：Figma 风格优化（Web + 桌面）

### 3.1 目标

以 Figma 的浏览/分页心智与设计令牌规范优化前端交互，并确保 **Web 与桌面壳**同源生效、可验证。

### 3.2 设计决策与落地

| 项 | 设计（参考 Figma 规范） | 实现 |
|---|---|---|
| 市场增量浏览 | 卡片流底部「加载更多」+ 已加载进度（`已加载 N / M`）+ 终点态（`已全部加载（M）`），不做传统页码条；按钮/文字严格用 `@dforge/ui` 令牌（间距 2/3、字级 11、圆角沿用） | `renderPagination`（page.tsx）+ `paginationStyle/paginationErrorStyle`（styles.ts，纯令牌） |
| 加载状态 | 按钮进入 loading 文案（`正在加载…`）并禁用，防重复请求；已载内容不闪不丢 | `useMarketPagination.loadMoreState` |
| 失败恢复 | 行内红字错误（`加载更多失败：…`）+ 按钮保留可重试；不清空已载卡片 | `paginationErrorStyle` + 保留 items |
| 计数语义 | 进度只表达「已载/总量」，与既有 `全局/当前结果` 的分面计数（E3）并存不冲突 | `market.list.progress/allShown` 新 i18n 键（zh+en） |
| 桌面端补全 | 标准「窗口」菜单：最小化 / 关闭窗口（Figma 桌面端同款的操作可达性）；不引入多标签等 P6 缓归项 | `menu.ts` + `menu.test.ts` 白名单与断言 |
| 两端一致性 | 桌面壳装载同一 Web 产物（`DFORGE_SHELL_URL`），分页与计数在壳内逐像素同构 | 壳冒烟截图 `shell-market.png`（1440×900@DPR1.5） |

### 3.3 输出与验证

- 输出：`useMarketPagination` + `pagination.ts`（纯函数）+ 页面分页行 + i18n（zh/en 各 5 键）+ 桌面窗口菜单 + 三层测试（hook 4 例 / 纯函数 3 例 / 页面 1 例 / 菜单 1 例）。
- 验证矩阵：
  - `pnpm verify` **exit 0**（2765 例：web 1343 · ingest 579 · engine 312 · ui 165 · desktop 122 · daemon 118 · contracts 80 · cli 45 · comfy 1）；
  - `pnpm e2e:smoke` **exit 0、63/63 步**（home 8 / editor 17 / nav 21 / canvas 10 / 门禁 7，零退化）；
  - 机器人 v3：**市场「加载更多」60→120、进度「已加载 120 / 344」**（截图 `m11-load-more.png`）；
  - 桌面壳：装载市场页自检 **failures=[]**、视口 1440×900@DPR1.5（`shell-selfcheck.json` + `shell-market.png`）；`verify-shell-parity` 冒烟 0 / 存活 0 / 对照 2（参照集未冻，预期）；

### 3.4 边界与未做

- 未引入「页码条/无限滚动自动加载」：前者与该页浏览心智不符，后者会与「本地优先、可控请求」的调试友好性冲突；按需可后续以设置项提供。

- 视觉逐页对照仍待 REF-01 参照集（与本批无关，门禁按 `exit 2` 阻塞且无假绿）。
